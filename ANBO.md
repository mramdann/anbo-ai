# ANBO.md

Anbo loads `ANBO.md` from the workspace root as agent memory (similar to AGENTS.md / CLAUDE.md). This file is also the project's living architecture doc - read it before making changes.

## Project

**Anbo**: open-source AI-native terminal emulator. Tauri 2 + Rust (`portable-pty`) backend, React 19 + TypeScript + xterm.js (webgl) client, BYOK AI via Vercel AI SDK v6.

- Bundle id: `com.anbo.desktop`
- Package manager: **pnpm**
- Platforms: macOS, Linux, Windows
- Frontend checks: `pnpm lint`, `pnpm check-types`, `pnpm test`
- Rust checks: `cd src-tauri && cargo clippy --all-targets --locked -- -D warnings`, `cd src-tauri && cargo nextest run --locked` (local fallback: `cargo test --locked`)

## Quality bar

Production-grade or it does not ship. Every change is judged against all of these, not just "it works":

- **Correctness**: edge cases, failure modes, concurrent access. No "works for now".
- **Performance**: ultra-lightweight is the product. ~7-8 MB bundle, high-performance terminal. For every change ask: how much RAM it costs, whether it adds IPC round-trips or redundant requests, whether it triggers extra re-renders or wasted work, whether it pulls a heavy dependency. Unused features consume zero resources.
- **Security**: no critical security holes. Validate at every boundary (IPC, fs, network, AI tool surface). The secret-path deny-list applies on both read and write and is never bypassed.
- **UI/UX**: polished, professional, premium. Every state and detail considered.
- **Architecture**: new or changed logic lives in pure, dependency-light functions (functional core); tauri commands and React components stay thin (imperative shell). Keeps it testable without a later rewrite.

Verify before claiming done:

- Frontend: `pnpm lint`, `pnpm check-types`, `pnpm test`
- Rust: `cd src-tauri && cargo clippy --all-targets --locked -- -D warnings`, `cd src-tauri && cargo nextest run --locked` (or `cargo test --locked`)

A change to a core subsystem (terminal/shell spawn, workspace auth, git, fs, IPC or AI tool surface) needs a test that locks the invariant.

## Conventions

- **Comments**: default to none, the code should explain itself. If genuinely needed, 1-2 lines on *why*, never *what*. No AI-generic filler.
- **No em-dash** anywhere: code, comments, commits, docs.
- **No emojis** anywhere.
- **Imports**: always `@/...` on the frontend, never relative across modules.
- **pnpm only**, never npm/npx/yarn.

## Architecture

### Two-process model

**Rust (`src-tauri/`)** owns all OS access. The webview never touches the FS, processes, or shells directly - everything goes through `invoke()` calls to commands registered in `src-tauri/src/lib.rs`:

- `pty::pty_*` - long-lived interactive PTY sessions (xterm ↔ portable-pty), managed by `PtyState` (`RwLock<HashMap<id, Session>>`). Output streams via a Tauri `Channel<PtyEvent>`.
- `fs::tree::*` (`fs_read_dir`, `list_subdirs`), `fs::file::*` (`fs_read_file`, `fs_write_file`, `fs_stat`, `fs_canonicalize`), `fs::mutate::*` (`fs_create_file`, `fs_create_dir`, `fs_rename`, `fs_delete`): file explorer + editor IO. Every renderer path is canonicalized and checked against `WorkspaceRegistry`; new targets authorize their nearest existing canonical parent. AI calls opt into the Rust protected-path guard.
- `fs::search::*` (`fs_search`, `fs_list_files`), `fs::grep::*` (`fs_grep`, `fs_glob`): fuzzy file finder + content search (powered by `ignore` + `grep-*` crates).
- `git::commands::*`: full source-control surface (`git_status`, `git_diff`, `git_diff_content`, `git_stage`, `git_unstage`, `git_discard`, `git_commit`, `git_fetch`, `git_pull_ff_only`, `git_push`, `git_log`, `git_show_commit`, `git_commit_files`, `git_commit_file_diff`, `git_panel_snapshot`, `git_resolve_repo`, `git_remote_url`). All gated through the workspace authorization registry.
- `shell::shell_run_command`: one-shot subshell exec used by AI tools. Distinct from PTY sessions; not the user's interactive terminal. On Windows via PowerShell (`-NoProfile -Command`), on Unix via `$SHELL -lc`. Shared helper `build_oneshot_command`.
- `shell::shell_session_*`: persistent agent shell with state across calls. `shell::shell_bg_*` (`spawn`, `logs`, `kill`, `list`): long-running background processes (dev servers etc.) with bounded ring-buffer log capture.
- `workspace::*`: `workspace_authorize` / `workspace_current_dir` (the spawn/git/AI cwd authorization registry) plus the WSL bridge (`wsl_list_distros`, `wsl_default_distro`, `wsl_home`).
- `lsp::*` (`lsp_detect`, `lsp_host_pid`, `lsp_resolve_root`, `lsp_spawn`, `lsp_send`, `lsp_kill`): language server process host. Dumb JSON-RPC pipe: Content-Length framing + process lifecycle in Rust (`lsp/framing.rs`, pure + tested), protocol intelligence on the frontend. Spawn cwd gated through the workspace registry; binaries resolve via the captured login-shell env (`lsp/env.rs`, GUI apps get a bare PATH on macOS); root detection walks up to markers but never to or above `$HOME`. Servers run in their own process group on Unix and are group-killed (cargo check / proc-macro children die with the server); Windows children get a `proc::job::ProcessJob` (kill-on-close, shared with pty). All sessions killed on `RunEvent::Exit`.
- `net::*` (`ai_http_request`, `ai_http_stream`, `ai_http_cancel`, `lm_ping`): AI HTTP proxy with SSRF guard; keeps provider calls and local-model pings off the webview. Redirects are followed manually, with scheme/host/DNS/IP classification and resolver pinning repeated for every hop. IPv4-mapped IPv6 is classified as IPv4. Stream cancellation reaches the Rust request and response body instead of only stopping frontend consumption.
- `secrets::secrets_*`: OS keychain via the `keyring` crate. Rust accepts only the `anbo-ai` service and bounded account/secret inputs. Linux uses a file-based fallback gated behind `#[cfg(target_os = "linux")]`.
- `project_memory::project_memory_read`: the only agent-memory reader. It canonicalizes the authorized workspace and `ANBO.md`, rejects symlink escapes/protected roots, and enforces 32 KiB before content crosses IPC.
- `open_settings_window`: separate webview window for Settings (optional `tab` arg deep-links a section).

### PTY shell integration

PTY shells are bootstrapped via injected init scripts in `src-tauri/src/modules/pty/scripts/`:

- **Unix** (`zshenv.zsh`, `zprofile.zsh`, `zlogin.zsh`, `zshrc.zsh`, `bashrc.bash`) for zsh/bash, plus a private runtime copy of `init.fish` loaded through Fish `-C`. No shell integration is written into the user's global shell configuration; startup removes only a historical Anbo-owned `~/.config/fish/conf.d/anbo.fish` file. Emit OSC 7 (cwd) and OSC 133 A/B/C/D (prompt boundaries + exit code) so the host can track cwd and detect command boundaries without re-parsing the prompt. Fish 4.0+ writes its own OSC 133 prompt markers; Anbo sets `fish_features=no-mark-prompt` and re-asserts its own prompt via `-C` to avoid doubling.
- **Windows** (`profile.ps1`) - passed via `pwsh -NoLogo -NoExit -ExecutionPolicy Bypass -File <path>`. Wraps the user's existing `prompt` function (after their `$PROFILE` runs) to emit OSC 7 + OSC 133 A/B/D. Shell priority: `pwsh.exe` (PS 7+) → `powershell.exe` (PS 5.1) → `cmd.exe` (no integration). cwd is normalized to backslashes before being passed to ConPTY (`CreateProcessW` misbehaves with forward-slash cwd).

`pty/shell_init.rs` is split into `#[cfg(unix)]` / `#[cfg(windows)]` modules - keep new platform-specific code in the right cfg arm.

Every PTY and one-shot shell drops the markers a running Claude Code stamps on its children (`CLAUDE_CODE_SESSION_MARKERS` in `shell_init.rs`: `CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_ENTRYPOINT`, session, pid, messaging and effort variables). When Anbo itself is launched from inside a Claude Code session, as the Dev launcher often is, a Claude agent that inherited `CLAUDE_CODE_CHILD_SESSION` turned transcript saving off, so no session JSONL existed and every restart relaunched it fresh instead of resuming; the inherited effort also made it open with a "use xhigh effort?" prompt. Settings the user puts in their shell profile are unaffected because the login shell reapplies them.

ConPTY on Windows requires `SPAWN_LOCK` (Mutex) around `openpty + spawn_command` in `session.rs`. Concurrent spawns leave one of the resulting PTYs with a stalled output pipe. Don't remove the lock without verifying first-tab stability under fast tab spam.

Each ConPTY child is also assigned to a per-session **Job Object** with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (`pty/job.rs`). When the Job HANDLE drops - clean shutdown, panic, or even SIGKILL'd Anbo process - the kernel kills every descendant of the shell (e.g. `npm run dev` spawned from inside pwsh). Without this Windows orphans the entire process subtree because `TerminateProcess` only kills the immediate child. macOS/Linux rely on `Drop for Session → killer.kill()`; on dev-`Ctrl-C` of `cargo run` destructors don't fire and orphans are possible there too - acceptable for now since dev only.

`AiComposerProvider` is mounted unconditionally at the App.tsx root: a conditional wrapper would change the parent element type when keys load, remounting the entire tree (and re-spawning every PTY) the moment `getAllKeys()` resolves. Production happened to dodge this because keychain reads can land in the same paint frame; dev didn't. Keep the unconditional wrap.

### Frontend (`src/`)

Single-window React app. Path alias `@/*` → `src/*`. Tabs are a tagged union (`kind`: `terminal` | `editor` | `browser` | `markdown` | `ai-diff` | `git-diff` | `git-history` | `git-commit-file`) and **not** unmounted on switch - they're hidden via `invisible pointer-events-none` so PTYs and dev servers keep streaming in the background.

`App.tsx` wires modules together - keep it a coordinator. New features go inside the appropriate `modules/<area>/`.

### Module layout (`src/modules/`)

Each module is self-contained, exports a thin barrel via `index.ts`, and owns its hooks under `lib/`.

Agent-created shared terminals use `terminal_open`, start warm in the requested workspace, and require a purpose-specific tab title. The first tab in an empty active workspace is selected; additional tabs remain in the background and inactive workspaces never activate. This placement policy is shared with browser and CLI-agent creation. `terminal_close` only closes an idle terminal opened by that tool during the current application session. User-created terminals retain their workspace-derived default title.

- **agents/** - Agent launcher instances map one-to-one to terminal tabs. The launcher defaults to one instance; selecting two to four creates independent tabs rather than a split group. Each agent tab persists its CLI identity and a case-insensitive workspace-scoped callsign. The first available instance keeps its canonical CLI name; later instances randomly draw without replacement from 20 curated aliases per CLI, the shared unused alias pool, and bounded generated fallbacks. Cross-space moves and restore repair collisions without changing resume metadata. The tab always keeps its colored CLI logo; activity is shown as a separate status badge. Codex input is acknowledged only after the terminal renders it; a startup or trust prompt returns a retryable not-ready error without pressing Enter or losing the instruction.
- **Startup surface** - The pre-React splash reports module and bootstrap errors immediately. A phase-aware watchdog distinguishes module loading, orphaned-terminal cleanup, workspace resolution, and React rendering. Progress resets the stalled-phase fallback, bootstrap steps retain their specific timeout errors, and readiness is emitted only from a React layout effect after the root commits. A generic 60-second timeout remains only for a module that never begins evaluating.
  Splash colors use a bounded, versioned local shadow of the committed theme's light and dark palettes before loading modules or invoking IPC. System mode is resolved at startup; custom themes use the same single-variant fallback as the theme engine. Temporary previews and unresolved custom themes must not replace this cache. Missing, stale, invalid, or inaccessible cache data falls back to the app's neutral light/dark colors. Restore only validated color tokens, never arbitrary CSS or background assets, and preserve the existing splash geometry, animations, and reduced-motion behavior.
- **terminal/** - `TerminalStack` keeps one mounted xterm per tab via `useTerminalSession` + `pty-bridge`. A shared invisible stack mounts warm terminal tabs from inactive spaces so MCP-spawned agents start and existing agents remain live without activating their workspace; restored cold tabs stay excluded until deliberately warmed. `osc-handlers.ts` parses OSC 7 (with Windows drive-letter normalization: `/C:/Users/foo` → `C:/Users/foo`) and OSC 133 markers. The xterm color palette is driven by the central theme engine (`modules/theme`), not a local table. Renderer buffers are pooled (`rendererPool.ts`): five warm buffers, up to 16 live buffers when active TUIs cannot safely be evicted, and a separate hard cap of five WebGL contexts. At the live-buffer limit, attachment/automation is refused with an actionable capacity notice. Pending xterm writes, alternate-screen buffers, busy retained buffers, and visible panes are ineligible for eviction. A hidden leaf with a foreground job (OSC 133 C..D, agent signal, or `pty_has_foreground_job`) keeps its live grid parked with rendering paused via `display:none`; an idle hidden leaf releases its slot but the buffer is retained and serialized lazily only when another leaf steals it. Revealing a parked WebGL slot waits for layout, refits the grid, and repaints from the intact buffer so workspace switches cannot expose a corrupted cached frame. Visible pane resize also schedules one debounced repaint after geometry settles. The shared xterm texture atlas is never cleared from an individual pane because doing so invalidates glyphs used by sibling WebGL terminals. Ordinary tab switches with unchanged pane geometry avoid delayed repaint work, preventing multi-pane flicker. The `DormantRing` (1 MiB, no terminal reset on overflow) buffers bytes only for leaves whose slot was stolen or never bound. Never serialize a leaf that is mid-command: replaying incremental TUI repaints over a snapshot is what used to wipe Claude Code. `terminalAutomation.ts` exposes only normal user-owned terminals through the shared terminal tools; private terminals, agent CLI tabs, cold or exited sessions, busy shells, and prompts containing unsubmitted input are protected from command execution. Shared terminal reads reconstruct logical lines from xterm wraps and distinguish unread output from omitted history or a repainted buffer. `terminal_execute` assigns an execution id before dispatch and advances it through queued, dispatched, running, and final states. Each OSC completion is retained in a bounded generation record, so `terminal_wait` freezes the exit code, completion reason, and final output for the matching execution instead of reading the terminal's latest global state. `terminal_interrupt` can cancel a queued execution before dispatch or target a dispatched/running execution by id. `terminal_insert` briefly verifies visible echo and returns a cursor when polling is still needed. Terminal metadata includes the actual shell label and grid dimensions. These actions never activate another workspace. Opening the first shared terminal in an empty active workspace selects it; later opens and other terminal actions preserve UI focus.

Windows resource admission: `modules/resource_guard.rs` samples system commit headroom before new PTYs, native browser children, and agent launches/resumes. Atomic 30-second startup reservations prevent concurrent requests from spending the same headroom; low memory returns `resource_exhausted` without stopping existing sessions. A restore-time resume that is refused is retried by `agents/lib/resumeAdmission.ts` every 10 s for up to 3 minutes (the earlier restores' reservations expire after 30 s), stops if the terminal closes or already runs an agent, and only then reports `Agent resume skipped`; a manual launch still fails immediately so the user can decide. This is admission control, not a guarantee against later growth in external agents/websites. No polling is added to terminal output, pointer movement, or startup idle paths. The Windows Event 2004 incident on 2026-09-08 exhausted system commit, not just physical RAM; do not reproduce it by deliberately exhausting the user's machine.
- **editor/** - CodeMirror 6 stack (`EditorStack` mirrors `TerminalStack`). `extensions.ts` configures language modes; supports vim mode. Buffers live in LF space and the original EOL (`lib/eol.ts`, majority-vote detection) is restored on save; indent unit/tab size are detected per file (`lib/indent.ts`) via a per-pane compartment. Saves are serialized and conflict-checked against the content version returned by `fs_read_file`/`fs_write_file` (mismatch → warning toast with explicit Overwrite, never silent last-writer-wins); external format-on-save only applies the disk read-back if the doc is unchanged since the save snapshot. Files over 10 MB offer "Open anyway" (hard cap 50 MB, `force` arg); above 4 MB syntax highlighting and LSP stay off. Cmd-F routes to CodeMirror's own search panel (find/replace/regex) when an editor tab is active, Ctrl-G opens go-to-line; both panels styled in `chromeTheme.ts`. Format-on-save formatters live in `lib/externalFormat.ts` (`FORMATTERS` registry: biome, prettier, ruff, rustfmt, gofmt, clang-format, shfmt, zig fmt, plus a custom `{file}` command template); `resolveFormatter` applies per-language overrides (`editorFormatterByLang`) over the global default, and a global external default only runs on languages its tool understands. Diff panes resolve the language before mounting CodeMirror: a late compartment reconfigure leaves the merge view's deleted-chunk widgets unhighlighted. AI inline completion (`lib/autocomplete/`) sends the buffer's indent unit with the request and normalizes unambiguous tab/space mismatches in responses (`normalizeIndent.ts`); triggering is `autocompleteTrigger` auto or manual, with `editor.aiComplete` / `editor.codeComplete` registry shortcuts (guarded to editor tabs so the keys fall through to terminals), and Tab accepts an open completion popup before the ghost. Multi-line ghosts render first-line-inline plus a block widget below the line (never inline `<br>`s); a closers-only line-suffix (cursor inside `fn(|)`) is hidden and re-appended after the block so the preview equals the accept result, and a line-suffix with real code caps the ghost to one line (`capToLineSuffix`). Suggestions echoing the recent prefix are dropped, multi-line suggestions and closing brackets never start on a line that ends with `;`, and closer-only lines are reindented from the previous line (`trimSuggestion`/`reindentClosers`, all tested). Markdown editing is GFM (`markdownLanguage` base) with fenced-code highlighting resolved through the shared lazy language registry, Cmd/Ctrl+Click URLs, and clickable task checkboxes (`markdownExtras.ts`, all inside the lazy markdown chunk; the eager-budget test enforces this). Dotenv files (`.env`, `.env.*`, and `*.env`) use the lazy shell grammar. Editor theme is decoupled from the app theme: the `editorTheme` pref is `"auto" | EditorThemeId` (default `"auto"`), resolved at render time by `useEditorThemeExt` via `resolveEditorThemeId`. In `auto` the editor follows the active app theme's `editorTheme[mode]` pairing (live, never stale); an explicit pick overrides. Theme ids + labels live in `settings/store.ts` (`EDITOR_THEMES`/`EDITOR_THEME_LABELS`); the matching extensions in `editor/lib/themes.ts` (`EDITOR_THEME_EXT`). Prebuilt `@uiw` themes plus locally-built ones in `editor/lib/cmThemes.ts` (Kanagawa wave/lotus/dragon, Everforest, Dracula, Solarized, Catppuccin, Rosé Pine) via `createTheme` (no extra deps). The three CM surfaces (`EditorPane`, `AiDiffPane`, `GitDiffPane`) all read the theme through `useEditorThemeExt`.
  Every editor also emits stable Lezer `tok-*` classes and has scoped, mode-aware global chrome and token fallbacks. The complete layout-critical CodeMirror base layer, including selection/cursor layers, gutter sizing, panels, and widget buffers, remains available globally if WebView2 fails to install a runtime `style-mod` module. The production editor smoke must validate document geometry, computed syntax color, and bounded absolute selection markers, not only visible text.
  Editor code size is stored separately as `editorFontSize` and does not affect `terminalFontSize`.
- **explorer/** - file tree with a generated Material Icon Theme subset (`iconResolver.ts`, `materialIconSet.ts`), fuzzy search, keyboard nav, inline rename, context actions. The generated subset keeps common development file and folder associations while unsupported names use Material generic fallbacks. Regenerate it with `pnpm generate:material-icons`. Backslash-aware `basename`.
  File and folder rows expose Rename in the context menu and via F2, including inline rename in search results. Renames refresh results and retarget editor and Markdown tabs only in the originating workspace environment. Inline rename selects file stems but full folder names, supports Enter/Escape, retains failed input for correction, and shows mutation errors. Names must stay in the same parent and respect Windows filename restrictions for Windows paths. Rename, drag-and-drop moves, and trash operations check unsaved editors before IPC; mutations are single-flight per explorer. Create failures retain the input; failed moves and trash actions display errors without optimistic tab updates.
  Explorer removal uses the separate authorized `fs_trash` command, never the permanent `fs_delete` AI command. Windows recycling runs on a bounded dedicated COM apartment with recycle-only flags, aborted-operation checks, and no connected-file deletion. Other desktop platforms use system trash through `trash`. Workspace roots, WSL paths, and Windows network paths are rejected; no permanent-delete fallback is attempted. The UI confirms moving to trash and explains system recovery after success.
- **browser/** - built-in browser tab (status-bar pill suggests opening when a localhost URL is detected). Each warm browser tab keeps a stable renderer owner across React/Dockview host handoffs. `BrowserStack` mounts browser tabs that have no visible Dockview panel in a shared background host, including tabs in inactive spaces, so agents, navigation, and media continue without activating the workspace or stealing focus. Closing a UI tab calls `browser_embed_close` and destroys its native child; a temporary React unmount calls owner-scoped `browser_embed_release` instead.
  On Windows, inactive native browser children stay visible to WebView2 at `HWND_BOTTOM`, parked completely outside their parent's client area without changing viewport size; the active child is placed at `HWND_TOP` with its visible bounds. Do not hide the host HWND or assign it an empty region: keeping only the WebView2 controller visible is insufficient and can stall CDP mouse movement or lose native input. Off-client parking prevents background pixels from leaking during restore without per-frame polling or global Chromium flags. Visible browser geometry is synchronized through `ResizeObserver`, shared resize/scroll/visibility/interaction/animation signals, and one 1.5-second fallback shared by all visible panes. Do not restore permanent frame polling or a document-wide `MutationObserver`. Overlapping React menus temporarily place the active child immediately below the transparent main-webview surface with `browser_embed_set_ui_overlay`. Dragging captures one frame only for a visible browser pane and clears its base64 data when the drag ends or the pane becomes hidden. Browser tabs show a theme-aware pulsing automation indicator while a CLI or the AI panel is operating on them.
  Foreground z-order changes and background parking are synchronous on Windows and never activate the application. Hidden panes are parked during the React layout phase and retain their last viewport dimensions while hosted in the shared background stack, preventing a background page from covering browser chrome during rapid tab or workspace switches. Suspend and restore paths use the same presentation policy and release the global lifecycle lock before native presentation calls. Dockview restores workspace layouts, panel membership, and the active panel in layout effects so the browser address bar never paints an intermediate missing state. Blank and validation-error browser panes remain opaque because the main window surface is transparent. The Windows browser child also remains opaque so a page with a transparent document canvas cannot reveal terminals or editors behind it.
  URL validation errors are derived from the current tab URL rather than retained across native navigation events, because sites may briefly report internal transition URLs before returning to HTTPS. `browser_tabs` obtains UI metadata without activating a space and reports the foreground browser, active space, per-tab `spaceId` and workspace root, loading state, automation target, and recent automation activity. Mouse preflight retries only idempotent DevTools calls; press/release use a longer bounded timeout to avoid duplicate clicks. Enter reports observed submit/navigation effects separately from successful key dispatch, and page reads retry short script calls across document transitions.
  MCP browser, shared terminal and agent open operations share one first-tab selection policy. They select their first tab only when the explicitly targeted workspace is already active and has no tabs of any kind. A pending first selection is reserved until React commits it so concurrent opens cannot both claim it. Later opens remain in the background; inactive workspaces never activate. Browser placement distinguishes `visible-first-tab`, `visible-background-tab`, and `inactive-workspace`. This does not resize/reposition the application or activate its OS window. `automationTarget` is the browser-routing selection, not a live-session flag.
  Native browser children use an isolated app-local profile, separate from the main Anbo webview. The blank browser page shows a bounded 100-entry browsing history plus measured profile size, and its clear action removes only browser history, cookies, cache, and site storage. Local `file:` navigation is accepted only after Rust canonicalizes the target and proves it remains inside that tab's authorized workspace root; relative assets and same-workspace page navigation continue to work.
  Explorer context menus offer `Open in Anbo Browser` only for common browser-renderable file types and create an encoded local file URL in the active workspace.
- **tabs/** - `useTabs` is the source of truth for tab list + active id. Tab and terminal-leaf ids remain monotonic for the renderer lifetime, including development remounts, so a stale PTY can never attach to a newly hydrated workspace tab. Browser automation targets are stored per `spaceId` and are separate from the UI `activeId`, so agents in different workspaces do not contend or change the user's foreground tab. Dockview reports which panels are actually visible; non-visible warm browsers are handed to the shared background host. The hidden-tab dropdown preserves favicon, loading, active-check, and automation states without stacking competing icons. `useWorkspaceCwd` derives explorer root + inherited cwd for new tabs from active tab. `basename` splits on both `/` and `\`.
- **header/** - top bar + inline search (`SearchInline` adapts to terminal vs editor via `SearchTarget`). `WindowControls` rendered when `USE_CUSTOM_WINDOW_CONTROLS` is true (Linux + Windows; macOS uses native traffic lights).
- Terminal and agent close confirmations retain one title/description snapshot through the dialog's exit animation, even after the pending tab or pane is cleared. A new confirmation captures fresh copy, including when reopening the same tab. Keep this presentation state separate from process disposal; no close delay, polling, or timeout is needed.
- **statusbar/** - bottom bar, `CwdBreadcrumb` (handles Unix paths, Windows drive letters, and home `~` segments via `pathUtils.segmentsFromCwd`), AI tools indicator.
- **shortcuts/** - keymap registry (`shortcuts.ts`) + `useGlobalShortcuts`. Handlers live in `App.tsx` and are passed in by id (`tab.new`, `ai.toggle`, …). `metaKey || ctrlKey` for cross-platform Cmd/Ctrl.
- **settings/** - settings store (`store.ts` via `tauri-plugin-store`), preferences hook, settings window opener.
- **sidebar/** - activity bar + collapsible side panels (explorer, source control, git history).
- **source-control/** - git status / stage / commit panel and diff workflow.
- **git-history/** - commit graph rail, refs, per-commit file diffs.
- **lsp/** - opt-in language server support, zero cost until enabled (no process, no PATH check, nothing in the eager bundle beyond a 14.5 kB shell). Statusbar pill offers Enable (binary found) or Install (with copyable command) per language; activation persists as `lspActivation` in the settings store (`enabled`/`dismissed`/unset). `sessionManager.ts` keys sessions by (server, workspace root), refcounts open docs, idle-kills after 3 min, and crash-backoffs (cooldown before respawn; 3 in 5 min → give up + toast with the server's stderr tail). Resource invariants: **no root marker → no session** (a dirname fallback once spawned a server per directory and burned GBs), hard cap of 4 sessions per server, lean per-preset `initializationOptions` (rust-analyzer: `cachePriming` off + bounded `lru`; tsls: `maxTsServerMemory`). Client is `codemirror-languageserver` behind a lazy import, subclassed (`lib/client.ts`) to add didClose/didSave/shutdown, `textDocument/references` (Shift-F12; multi-result definitions and references share the `locationsPanel.ts` picker) and the publishDiagnostics capability the lib forgets (tsls sends no diagnostics without it); `lib/transport.ts` bridges to the Rust pipe and answers server-to-client requests the lib ignores. `vscode-languageserver-protocol` is aliased to a 4-enum shim in vite.config.ts (~117 kB saved). Presets: typescript, rust-analyzer, pyright, ruff, gopls and more; custom stdio servers via Settings. Several presets can claim one language (pyright and ruff both take `py`): `serverForLanguage` prefers the enabled candidate, so enabling ruff while pyright is unset or dismissed routes Python to ruff. WSL workspaces excluded for now.
- **markdown/** - markdown preview renderer (backs the `markdown` tab kind). Preview IO and rendering are deferred until the tab is visible, and the backend enforces a 2 MiB preview limit before content crosses IPC; larger files remain available through raw editor mode. Fenced code previews are capped at 64 KiB or 1,200 lines per fence, with Raw retaining the full source. Streamdown stays in static mode with its sanitize/harden pipeline, explicit safe URL transformation, and link confirmation. Mermaid rendering is not enabled. The transitive Mermaid and DOMPurify versions are pinned through `pnpm-workspace.yaml` to patched releases, and production dependency advisories at moderate severity or above block both CI and release builds.
- **workspace/** - workspace environment switching (Local + WSL distros). Environment adoption is generation-guarded. Resetting one space closes and replaces only that space's tabs and handles; terminals, agents, browser media, automation, and dev servers in every other space remain mounted and running.
- **theme/** - custom theme engine (no `next-themes`). `ThemeProvider` + `applyTheme` write CSS variables; built-in presets in `themes/` (anbo-default, claude, kanagawa, kanagawa-dragon, tokyo-night, catppuccin, rose-pine, everforest, nord, gruvbox, dracula, solarized, tide, sage, caffeine), each optionally declaring an `editorTheme` pairing consumed by `resolveEditorThemeId` (see editor/). ### Browser automation & MCP

Browser ref identities live in bounded weak-reference registries inside the automation isolated world, shared by find, snapshot and all ref consumers. Cloned `data-anbo-*` attributes never authorize a replacement node. Main-document context ids are cached by native navigation generation, bounded and removed on tab close/shutdown; cold setup must not become repeated frame-tree IPC on every input. Registry lookups replace whole-DOM ref searches and generation cleanup touches only remembered nodes. Text reads follow the composed shadow/slot tree, preserving render order and excluding inactive fallback or unslotted light children; compound and legacy text waits share this reader. One rule decides where a piece of text ends, shared by get_text, the accessible name and the snapshot: inline boxes join as the page wrote them however many elements it split them across, and only a non-inline boundary starts a new line, so a ticker that redraws a changing digit reads as one number everywhere. A scan claims a ref generation but only spends it when it registers a ref, so a lookup that matches nothing leaves the refs the caller already holds alive. A retry backs off and skips the walk entirely while the document's mutation counter, identity and animation state say nothing could have changed; a page Anbo cannot observe is never called quiet. A locator wait demands a unique match unless minCount says how many are enough, snapshots page with offset/nextOffset rather than by scrolling, and a failed find reports which of three things happened: confirmed absence, matches filtered out as not rendered, or coverage that never finished. `scripts/browser-correctness-smoke.mjs` tests these invariants through native MCP with owned loopback tabs.

Refs also retain the resolved destination of their nearest composed-tree link. Reusing a connected node for another URL invalidates its old ref on lookup, including link descendants, slots, SVG links and child frames; ordinary label, clock and input updates remain valid. Destination checks walk at most 257 ancestors and retain at most 8,192 URL characters per ref; an oversized URL or incomplete ancestry fails closed, without prefix matching or a permanent observer. Non-link controls and their descendants additionally retain the nearest recognizable item context: list items, table rows, articles, matching ARIA roles, explicit `data-item-id`/`data-id`/`data-key`/`data-video-id`, or repeated custom elements within eight siblings in either direction. Context fingerprints compare the container object, explicit identity attributes and a sorted set of resolved links, never live labels, clock text or input values. Each context scan visits at most 256 elements, retains at most 16 links and 16,384 identity/URL characters. Large subtrees fall back to container and explicit attribute identity, without claiming destination coverage; oversized identities fail closed. This is bounded heuristic protection, not a fingerprint of arbitrary JavaScript handlers.

Native main-document clicks revalidate identity, visibility, enabled state, coordinates and the actual hit target after pointer movement before each mouse-down, in one bounded `pointerGuard` diagnostic phase. This adds one script IPC for ordinary controls and replaces the previous identity-only IPC for links and recognized items. Visible, hittable controls are not recentered; other targets get one instant scroll before stability sampling, never repeated scrolling during the wait. Frame clicks revalidate identity after focus and before each click. Identity drift returns `stale_ref`; changed pointer targets return `input_not_ready` with a bounded reason and the number of clicks already dispatched. Neither retries input automatically. Guard reasons never expose captured URLs or item contents. Changes after the guard, inside a click handler or during later redirects remain outside the guarantee. `scripts/browser-ref-destination-smoke.mjs` covers destination/context mutation and latency; `scripts/browser-pointer-smoke.mjs` verifies trusted input, hover layout races, partial double-click failure and retained SPA state through native MCP without changing application window geometry.

Main-document dialog capture remains in the page world after isolated ref/actionability validation, so page handlers use the temporary alert/confirm/prompt hooks. Ref evaluation retains ExecuteScript-compatible JSON serialization, including plain URL strings used for popup routing. Click actionability selects a painted client-rect fragment for wrapped inline links instead of targeting empty space at the center of their combined bounds; fragment inspection is capped at 32. Locator comparisons normalize the requested values once per scan and skip empty roles before name matching. `scripts/browser-locator-benchmark.mjs` compares loopback MCP endpoints using paired, alternating samples and explicit scan-cap checks without changing application window geometry.

Page-info and snapshots report `titleSource`. Page-info defaults to native title/URL reads without document JavaScript; `titleSource: document` explicitly requests a bounded DOM-title read and never silently falls back. `waitFor.titleSource` accepts native or document and defaults to document for compatibility. Native-only title waits avoid document scripts; combined conditions still verify document URL/text with the same stability window. Tab-list titles identify UI metadata versus native fallback. Locator results and timeout diagnostics distinguish a reached node cap (`nodeLimitReached`) and skipped frames from a complete no-match scan, without increasing scan limits.

Native mouse drag measures source and destination together after scrolling and checks both again after pointer movement, before pressing. Both endpoints must be visible in the same viewport; impossible layouts fail before mouse-down instead of using stale coordinates. HTML5 and child-frame DOM fallbacks remain explicit. Download records retain a separate canonical PathBuf for workspace authorization; normalized display paths are never used as identity. Dialog responses distinguish `clickDispatched` from `dialogOpened`, with `ok:false` when the click produced no dialog, so callers must not automatically repeat it. Legacy wait conditions record one bounded `condition` diagnostic phase; explicit postconditions retain their own phase.

The browser tab's agent logo stays still while two circular rings expand outward using CSS transform/opacity, stopping when idle or reduced motion is enabled. Native cursor and card share bounded distance-aware CSS transitions (up to 420ms), and the click ripple travels with the cursor. This is visual interpolation only: no added input delay, synthetic mouse events, per-frame JavaScript loop, or extra animation IPC. Navigation/caller changes still reset unverified coordinates.

Native page-info reads take title and committed URL from WebView2 properties without waiting for document JavaScript. Network-idle observation is installed before the initial navigation and retains only bounded request ids and activity timestamps, never headers or response bodies. Completion/failure events end requests; 500ms of continuous quiet plus non-loading state is required. Observer failure or overflow returns an error instead of false success. There is no network polling timer or per-request frontend IPC. Long HTTP streams can prevent idle; WebSocket traffic and other CDP targets are outside this page-target observation, so explicit readiness postconditions remain preferable.

Keyboard modifiers are per-call, not persistent across browser tools; pass the combination on each key. Control, Alt, and Meta shortcuts do not insert printable text; Shift-only maps letters and US-layout symbols. Persistent held-modifier ownership and modified mouse clicks are not supported. Type fills the value and emits input/change once, not per-character key events. Screenshots capture the viewport and exclude automation effects. Upload/download response paths use normalized display paths while authorization retains canonical native paths.

Find, snapshots, actionability, ref visibility waits, and text-read visibility metadata share a rendered-element policy. It checks transparent ancestors through native `checkVisibility` with opacity/visibility options, with a bounded composed-tree fallback covering Shadow DOM hosts and slots. Offscreen rendered elements remain discoverable; hidden file inputs remain available for uploads. Text results include `visible`: a hidden accessible label is not reliable live state. Hover accepts an optional position with x/y fractions strictly between 0 and 1 within a painted target fragment, defaulting to the center. The requested point participates in scrolling, stability and hit-target checks; target highlight bounds retain their true center. For auto-hiding video controls, explicitly hover the video and then move within it, for example position {x:0.6,y:0.5}. Entry-only or repeated center movement can be ignored by players that cache mouseover coordinates. Immediately start a bounded visible-ref wait and read the displayed clock once revealed. Reveal animation, auto-hide, ads and paused playback must be distinguished from an actual media stall; CSS hover alone is not playback evidence. Do not add automatic hover movement, click retries, or permanent media polling to mask hidden controls.

Browser geometry updates only set bounds and presentation for an existing native child; they must never replay the renderer URL. New children record the initial target before construction and clear it on failure; explicit navigation remains separate. On Windows, native WebView2 SourceChanged events synchronize SPA URLs to the owning renderer even in background tabs, without page scripts, polling timers, loading-state changes or ref-generation invalidation. Events retain the app-origin and authorized local-file navigation policy. URL reads use the native Source property through a bounded asynchronous main-thread call, keeping the committed address inspectable while response headers or page scripts are stalled. `scripts/browser-navigation-smoke.mjs` holds fixture responses to verify responsive reads, retained pending targets, single initial navigation, explicit subsequent navigation, and scoped cleanup.

Snapshot collection prioritizes visible candidates before the global item cap, including when merging child frames; title and URL metadata share the output character budget. Each find attempt allocates its generation under the tab lock, and its deadline includes queueing and frame scans. Late script execution cannot overwrite newer refs. A satisfied root locator skips child-frame work. Enter observers remove their listeners and timers on completion or failure, with bounded fallback cleanup; `observationTimeout: 0` skips observer installation entirely.

Click, press, and wait accept optional `waitFor` postconditions combining a URL glob, a whitespace- and case-normalized title, and a case-insensitive visible-text substring; the text probe reads the native `innerText` first and falls back to a composed walk of shadow trees, so it is not bounded by the snapshot's 16k-character reader (measured: a TradingView dialog appended after 16k characters could never match). Every supplied condition must match across a bounded stability window (200ms default, sampled every 100ms); transient mismatches or navigation restart that window. Use `waitFor.timeout` for its deadline, and do not combine it with legacy wait fields. Explicit press postconditions replace the default Enter observation. Waits release the tab lock between polls. A postcondition timeout after dispatch never repeats the click or key automatically; a condition that matched at least once but never held for the window returns `matched: true, stable: false` with `firstMatchedAtMs` instead of an error, and one that never matched fails with the title and URL the page showed. Press also accepts a current input `ref` and optional `expectedValue`, checked after native focus preparation and before key-down; mismatches fail without sending the key. Type's `valueVerified` describes only the immediate value, not subsequent SPA state. Native diagnostics are opt-in (`diagnostics: true`), bounded per action, and record phase durations without input values; error messages retain the error code and timings. Text reads exclude script/style/template and hidden subtrees with bounded traversal; `totalLengthIsLowerBound` marks collection truncation. `scripts/browser-readiness-smoke.mjs` exercises these contracts in owned loopback fixture tabs; `scripts/browser-automation-benchmark.mjs` covers refs, frames, caps, and legacy form submission.

Agent-facing cost, measured on 2026-09-12 with Claude Code driving the tools through MCP (15 tasks per tool; a deterministic harness and an LLM-driven one, both kept in the Dev sandbox rather than the repo): the first browser tool opens the control session itself, so `browser_start_session` is optional and only claims a tab early; tool replies are compact JSON, and `browser_screenshot` adds an MCP `image` content block for captures up to 600 KB (`inline: false` opts out); `browser_drag` advertises `sourcePosition`/`targetPosition`; `browser_find` computes implicit roles for headings, searchboxes, dialogs, lists, tables and landmarks, and a searchbox also answers to `textbox`; the built-in `anbo` skill declares `sections: on-demand`, so `skills_read` returns about 3.5k characters of essentials plus a section index and `section` fetches one section (20k characters were read at the start of every task before). `mcp::tests::browser_tool_schemas_fit_the_token_budget` keeps the browser tool schemas under 38k characters (44.8k before the trim), mostly by embedding the `locator` object without its prose. A second round, measured against Playwright MCP on the same model and correct setups (Anbo 14 calls per task to Playwright's 11, the whole Wikipedia gap being `browser_get_url` and `browser_end_session`): every navigation-shaped action (click, double_click, press, key, wait, navigate, reload, back, forward, dialog) now returns `page {url, title, loading, pendingUrl?}` read natively after it runs; `browser_close {endSession: true}` closes the last tab and ends the session in one call; `browser_get_property` reads a closed list of plain DOM properties (`paused`, `currentTime`, `value`, `checked`, `scrollTop`...) by ref without page JavaScript, replacing the find/focus/key probing an agent otherwise spends on media state; and every numeric parameter is read through `as_count`, which truncates a finite float instead of silently falling back to the default (`timeout: 400.5` used to mean 5,000 ms).

Browser automation (Windows only) controls live native browser tabs without requiring them to be visible or active. Three entry points share one backend (`actions::handle_action`):

- **In-app AI panel**: direct in-process Tauri command `browser_automation_handle_action` — fastest, no setup.
- **`anbo-browser` CLI/MCP** (`anbo-browser mcp --stdio`): a standalone stdio client that bridges to the running app over an authenticated named pipe. Built by `pnpm prepare:browser-sidecar`, bundled by the Windows Tauri config, and registered by the installer. This is the preferred external-client transport because token discovery is automatic.
- **HTTP MCP server** (hosted by the running app): Streamable HTTP at `http://127.0.0.1:7331/mcp`, with JSON responses and no SSE. Initialize returns a bounded, expiring session id; clients must forward `Mcp-Session-Id` on subsequent calls to retain private session ownership. Header-free legacy calls remain generic. The server is loopback-only, Origin-validated, request-size bounded, and exposes `browser_*`, `agent_*`, and `terminal_*` tools.

Enable/disable with **Settings → Browser automation** (default on); the toggle starts/stops both transports, and `browser_automation_status` returns `{ running, mcpUrl }`. Implementation: `src-tauri/src/modules/browser_automation/{http,mcp,server,actions,download,locator}.rs`.

Full automation capability is intentional: keep it enabled by default and do not add per-action approval prompts. Security and reliability work must preserve background navigation, click, typing, screenshots, and tab lifecycle operations while enforcing explicit workspace routing, loopback-only transport, bounded input/output, and deterministic cleanup.

`browser_open` and `browser_close` require an explicit workspace root or space id. Open selects the first tab only in an empty active workspace; later opens stay background and inactive workspaces never activate; close removes both the React tab and native WebView lifecycle state. Other actions target an explicit `tabId` and serialize through a per-tab lock. Click and keyboard actions use DevTools `Input` events, including focus emulation for background pages, instead of synthetic DOM events. Accessibility refs include their snapshot generation (`g3-e12`); creating a newer snapshot deterministically rejects every older ref before DOM lookup. Snapshot output is viewport-first and hard-bounded to 2,000-16,000 characters (8,000 default), reports truncation, and directs callers to scroll and snapshot again instead of reading an entire large page into model context.

`browser_find` provides bounded semantic locators for role, text, label, placeholder, test id, title, alt text, and CSS. Role locators can filter by a bounded DOM accessible-name approximation shared with snapshots and get_text fallback. Referenced labels precede aria-label and associated labels; button/link contents precede tooltips, and input labels precede title/placeholder. Editable values never become names. This is not full W3C accessible-name computation. Each find creates fresh generation-scoped refs, searches the main document, open Shadow DOM, and bounded child frames, returns at most 20 matches, and never requires a full snapshot. Child-frame work uses bounded concurrency with deterministic order. Click, double-click, focus, type, check, hover, and drag check visibility, enabled/editable state, stable geometry, and an unobscured hit target before dispatch. Offscreen rendered elements remain discoverable but report an outside-viewport action error if scrolling cannot expose their click point. Drag targets must stay in one document or frame.

`browser_wait` supports text, exact or wildcard URL, document load, bounded network-idle observation, and ref states including attached, detached, visible, hidden, enabled, disabled, checked, and unchecked. The original text-only contract remains compatible. `browser_key` adds press, key-down, key-up, and modifier combinations, while `browser_dialog` accepts or dismisses JavaScript dialogs. A permitted HTTP(S) popup is denied as an unmanaged native window and recreated as a managed background Anbo browser tab in the source tab's workspace. The browser profile remains one persistent app-local global profile; this P0 surface does not introduce per-workspace or per-agent profile isolation.

Every successful `browser_*` response includes `durationMs`. `browser_tabs` and `browser_get_url` report the last committed `url`, `loading` and `pendingUrl` while a known navigation target is still loading. The pending target is not evidence of a committed navigation and clears after completion. Enter key dispatch remains serialized, but its configurable submit/navigation observation window runs after releasing the per-tab lock so stop, navigation, and unrelated actions remain responsive. Run `pnpm benchmark:browser-frames -- --workspace C:/path/to/open/workspace` against a running development app to record p50 and p95 latency for find, snapshot, and text wait on pages containing 1, 10, and 32 total frames.

Enter navigation observation uses a native per-tab generation counter, so a fast reload or POST back to the same URL is still reported. Main-document hover sends native DevTools movement once and verifies CSS `:hover`, without replaying DOM mouse events. Child-frame hover retains its explicitly reported DOM fallback. Console capture retains the newest 50 bounded page-JavaScript messages across accessible frames, preserves log/info/warn/error/debug/trace/assert levels, records only failed assertions, and includes runtime errors plus unhandled rejections. Original console methods run once; mirror writes are coalesced per microtask. Native browser-internal warnings are not guaranteed.

File automation is workspace-confined. `browser_upload` attaches 1-16 existing files to a current `<input type="file">` ref through DevTools without opening the native file chooser or reading the file bytes into model context. Relative paths resolve from the tab's canonical workspace root; absolute paths, symlinks, and canonicalized targets are rejected when they escape it. Hidden file inputs, open Shadow DOM, child frames, `multiple`, `accept`, selected names, MIME types, sizes, and total size are handled explicitly. Selecting files does not submit a form: the caller must use a separate click or key action and verify the resulting page state.

`browser_download` arms exactly one automation-owned download for a tab, then clicks a current ref. Native WebView download events route that file into `<workspace>/.anbo/downloads` with a safe collision-free name; existing files are never overwritten. It returns a stable `downloadId`, and `browser_download_status` / `browser_download_wait` provide bounded polling for large transfers with terminal `completed`, `failed`, or `cancelled` states, verified path, and final size. Source URLs redact credentials, query strings, and fragments. Manual downloads that were not explicitly armed retain the WebView's normal destination flow. Closing a tab or exiting Anbo clears its in-memory automation download state without deleting completed user files.

Agent communication uses `agent_spawn`, `agent_list`, `agent_status`, `agent_read`, `agent_send`, and `agent_wait`. Every call requires an explicit workspace root or space id and never activates another workspace. Agent spawn selects its first tab only in an empty active workspace; later spawns and other agent actions preserve the selected tab. `agent_spawn` accepts a built-in launcher id or label, or the display name or internal id of a custom CLI registered in Settings. It creates one terminal and launches only the stored command; callers cannot supply or override shell commands. Agent ids are readable and scoped by the required workspace, using `<callsign>-<cli>:<tabId>` or `<cli>:<tabId>` for the canonical first instance. Legacy and provisional ids remain accepted as lookup aliases. Spawn returns stable tab, leaf, space, and agent metadata, with `pending: true` when live CLI detection exceeds the bounded wait. The first message to an MCP-spawned terminal may be delivered once while its startup state is still working; after that, normal readiness and acknowledgement serialization applies. Readiness is derived from the rendered CLI and bounded exact-session evidence, without installing CLI lifecycle hooks. The registry includes only live detected terminal agents and excludes private terminals. Reads peek the live renderer, serialized snapshot, or bounded dormant output without consuming terminal state; results are secret-redacted, cursor-based, and bounded to 12,000 characters. Sends are bounded, serialized per target, wait for a ready prompt by default, and support optional sender ids plus idempotency keys. Initial and Codex deliveries wait for the typed text to appear in the terminal buffer before pressing Enter, preventing startup or heavy-load input races. Setting `waitForReady: false` bypasses status waiting but retains this input-delivery handshake. A second queued send cannot enter the terminal until activity from the previous delivery is observed. MCP intentionally has no agent close operation; destructive lifecycle ownership remains with the user.

Shared user terminals use `terminal_list`, `terminal_read`, `terminal_insert`, and `terminal_execute`. They require the same explicit workspace routing and never activate a workspace, tab, pane, or focus target. Stable ids use `terminal:<tabId>:<leafId>`. The list excludes private tabs, agent CLI tabs, and terminal leaves currently claimed by live agent discovery. Reads are secret-redacted, cursor-based, and bounded to 12,000 characters. Insert and execute accept one bounded line only and revalidate that the PTY is attached, at a prompt, and has no foreground process immediately before writing; busy, starting, exited, or disappearing terminals fail without partial execution. `terminal_insert` does not press Enter and reports whether its text became visible. `terminal_execute` queues a visible command for bounded cancellable dispatch and writes a PowerShell-compatible CR so the user and agent share the same live terminal and output. The AI Panel exposes the same tools, with explicit approval required for insert and execute.

Automatic agent MCP setup is opt-in per CLI in Settings and defaults on for Claude, Codex, Antigravity, and OpenCode. Configuration stays project-local and uses each client's isolated file: `.claude/anbo-mcp.json`, `.codex/config.toml`, `.agents/mcp_config.json`, and `.opencode/anbo-mcp.json`. Claude receives its workspace-relative file through `--mcp-config .claude/anbo-mcp.json`; OpenCode receives its file through `OPENCODE_CONFIG`. Anbo adds or removes only the exact `anbomcp` entry it owns and refuses to replace a conflicting entry or invalid configuration. On the first enabled Claude launch, the historical root `.mcp.json` entry named `anbo-browser` is removed only when its type and loopback URL exactly match Anbo; every foreign server and top-level property is preserved.

Antigravity supports workspace `.agents/mcp_config.json` with `serverUrl`, as documented in its [official MCP guide](https://www.antigravity.google/docs/cli/mcp/). The generated configuration is header-free because the HTTP server accepts only loopback connections. The named-pipe sidecar continues to use the per-install token automatically, and no token is written into project files.

### Releasing to GitHub

Releases use [release-please](.github/workflows/release-please.yml) with the **Release PR** model. Never bump versions or edit `CHANGELOG.md` by hand — release-please does both from conventional commits.

1. **Land conventional commits on `main`.** `fix:` → patch, `feat:` → minor, `!` / `BREAKING CHANGE:` → major. `docs:` / `test:` / `chore:` do not bump. Version sources (`package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`) are bumped by release-please. The `anbo` entry in `Cargo.lock` carries the generic updater annotation and must be included in the Release PR; `scripts/check-version-sync.mjs` validates all four files without mutating a CI checkout.
2. **release-please opens a Release PR** titled `chore(main): release X.Y.Z` on each push to `main`; it accumulates pending changes until merged.
3. **Merge the Release PR (squash).** Release Please is PR-only and never publishes directly. After the merge, automation waits for the exact merge SHA to pass the full `CI` workflow, creates the tag plus a draft release, and builds the Windows NSIS installer in GitHub Actions. With `SIGNPATH_ENABLED=true`, it submits that artifact to SignPath, validates the returned Authenticode certificate, and regenerates the Tauri updater signature against the signed file. With the variable set to `false`, it retains the unsigned installer and clearly records the `Publisher: Unknown` risk. Both modes require the updater signature, exact installer hash, packaged WebView2 frontend-ready smoke, patched `latest.json`, and atomic draft publication. Publication replaces the merged PR's `autorelease: pending` label with `autorelease: tagged`; any failed verification leaves the release as a draft.
4. **Verify before announcing.** Tag exists, both `Release Please` and `Release` are `completed/success`, the GitHub Release is no longer a draft, and the live manifest reports the new version:
   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" https://api.github.com/repos/mramdann/anbo-ai/git/refs/tags/vX.Y.Z   # expect 200
   curl -sL https://github.com/mramdann/anbo-ai/releases/latest/download/latest.json | python -c "import sys,json;print(json.load(sys.stdin)['version'])"
   ```
   Assets appearing in a draft are not completion evidence. Wait for the workflow run to reach `completed/success` and for the release to be published.

Merging the Release PR when `gh` is not authenticated — the git credential helper holds a usable token, so use the API:

```bash
TOKEN=$(printf "protocol=https\nhost=github.com\n\n" | git credential fill 2>/dev/null | grep '^password=' | cut -d= -f2-)
curl -s -X PUT -H "Authorization: Bearer $TOKEN" -H "Accept: application/vnd.github+json" \
  "https://api.github.com/repos/mramdann/anbo-ai/pulls/<PR_NUMBER>/merge" -d '{"merge_method":"squash"}'
```

**Updater.** Installed apps poll `releases/latest/download/latest.json`. Since 0.12.1, auto-check is always on (30-min poll); a dismissed version is remembered so the modal does not reappear for that version, and Settings → About → "Check for updates" always re-surfaces it. Builds before 0.12.1 never auto-polled (the `VITE_UPDATER_ENABLED` gate was unset in release builds) — those devices must use the manual check.

**CI status and release relationship.** As of 2026-08-13, `main` CI is green across frontend, Linux Rust/clippy/nextest, Windows, macOS, and coverage. The browser embed must not call `WebviewBuilder::transparent(true)` on macOS unless the `macos-private-api` feature is deliberately enabled, and non-Windows cfg branches must still consume platform-only payload fields so `clippy -D warnings` stays clean. Release publication is gated on the successful `CI` push run for the exact tag SHA. Release actions are pinned to immutable revisions, and no downloaded repackaging tool is used by the Windows-only release workflow.

Scanners skip `ANBO-DESIGN-LAYER`. The frontend chrome is a lazy chunk (`browser/design/`), the per-tab status lives in a module store keyed by tab id, and nothing runs while the mode is off: no script in the page, no listener, no polling. The chrome inside the page (note editor, hint pill) paints itself with the app's popover, border, muted and primary tokens plus the resolved mode: the pane reads them off the document when the mode is switched on and again after every theme change (`design/designTheme.ts`, one call per change, deduplicated by value), Rust keeps only colour-shaped text and the layer sets them as custom properties on its host, which an inline `all:initial` does not reset. Mark colours stay fixed so they contrast with any page. A mark's `locator` hint uses `role` only when `browser_find` can derive that role from the tag or it is an explicit `role` attribute; other elements hint `testId`, `text` or `css`, so every hint resolves. `designLayerScript.test.ts` drives the shipped script through `node:vm` against a fake DOM; `design.rs` tests cover bounds, URL keys, naming, confinement and binding parsing.

- **Windows input callback reentrancy:** Tao 0.35.3 can call `PeekMessageW` while holding its keyboard or IME state mutex. Windows may synchronously re-enter the subclass callback during RDP or display-session transitions, causing the UI thread to deadlock on the same non-reentrant mutex. `src-tauri/Cargo.toml` pins Tao to upstream commit `c704261c519c58cfdd0bc2d58ba24e06a0b71c92`, which moves those message peeks outside the locks. Keep the exact pin and `pnpm check:native-patches` guard until a released Tao version contains that fix.

- **React 19 strict mode** double-mounts `useEffect` in dev → terminals spawn twice on first render. The first PTY is cleaned up almost immediately. The `SPAWN_LOCK` mutex serializes this; don't be alarmed by `pty opened id=1` followed by `pty closed id=1` in dev logs.
- **Windows PowerShell process lifecycle**: `killer.kill()` from `portable-pty` only kills the immediate child. Descendants (e.g. `npm run dev` started inside pwsh) survive unless something else takes them down. The Job Object in `pty/job.rs` handles this for the Anbo-process-death case; an explicit `pty_close` from JS also kills only the immediate child + relies on the Job to take the rest. Don't disable the Job without a replacement.
- **Tab `cwd` storage**: comes from OSC 7 with forward slashes (after `parseOsc7` strips `/C:` → `C:`). Anything that consumes `tab.cwd` and passes it to a Rust fs command on Windows must normalize separators or accept both forms - `apply_common` in `pty::shell_init` handles this for PTY spawn; other call sites must do their own.

Long initial-agent and Codex input handshakes send at most 256 UTF-16 units per chunk without splitting surrogate pairs, acknowledging each echoed prefix before the next chunk and one final Enter. Long Claude follow-up messages use the same handshake. All chunks share one deadline; a missing echo cancels without retrying input. Collapsed paste placeholders never prove message contents, and idempotency keys remain reserved after uncertain delivery. This adds bounded work only during an explicit send, not background polling.

Single-target browser actions accept exactly one fresh `ref` or a strict `locator` (`by`, `value`, optional `name`, `exact`, `includeHidden`, and lookup-only `timeout`). Locator resolution requires a unique match across complete bounded root/frame coverage; ambiguous or incomplete scans never dispatch input. Only lookup is retried, never a click or submission. Existing identity, destination, visibility, editability, hit-target and postcondition guards still apply after resolution. Drag retains two same-generation refs. Locator waits use `locator` + `state` with a top-level timeout, include hidden elements, and reject mixed legacy/compound wait modes. `absent`/`detached` need zero matches; `hidden` permits absent or one invisible match, always with complete coverage. Find metadata includes `editable`, `readOnly`, `inViewport`, and frame-local `bounds`, not a promise that clicking will succeed. Password values remain redacted.

Browser close and reconciliation share the same per-tab lock and re-read native ownership after acquiring it. Never remove a live lock from the registry while an owner or waiter still holds it. Renderer-owner transfers within the same instance retain native handles and navigation/loading state. An already absent registry entry and webview is an idempotent close; an unknown zero handle is not proof of destruction. Native waits run outside the global lifecycle lock, and failed cleanup retains retryable state. Windows forced child destruction requires the live HWND ownership property installed at creation; a recycled or unmarked handle is never destroyed by fallback.

Browser startup reservations are owned by native child records and released on record disposal after close. Failed creation releases its uncommitted reservation. Owner transfers retain it, failed close does not discard it, and any remaining reservation still expires after 30 seconds. Rapid sequential open/close must not accumulate reservations for already destroyed children; concurrent live startups must continue to reserve independently.
